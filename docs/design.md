# 設計メモ（時計修理工房）

## 目的
時計職人の実際の作業工程を、ブラウザの3Dゲームでリアルに体験できるようにする。
「正しい道具 → 正しい順番 → 力加減・角度・手ブレ・タイミングの操作」で工程が進み、
雑な作業は傷・紛失・破損として仕上がりと報酬に響く。

## 技術
- Three.js 0.170 + Vite 5（JavaScript）。3Dモデルはすべてコードのジオメトリで作る
- UI は HTML/CSS（日本語）、ミニゲームは Canvas 2D
- セーブは localStorage（キー `wr-games-save-v1`）
- テストは Vitest（ルールとデータの整合性）

## 3つの層
| 層 | 場所 | 役割 |
|---|---|---|
| データ | `src/data/` | 時計・部品・工程・道具・消耗品・お客さん・失敗。コードを書かずに増やせる |
| ルール | `src/procedure/`, `src/sim/` | 工程の進行判定、採点、時計の内部状態と測定値 |
| 表示 | `src/world/`, `src/bench/`, `src/watch/`, `src/ui/` | 3D と画面 |

## 工程データの考え方
- 工程は一本道ではなく **依存関係（needs）** で書く。`a|b` は「aかbのどちらか」
- `target`（クリックする部品）と `tool`（正しい道具）の組み合わせで工程が始まる
- `wrongTools` で、間違った道具を使ったときの失敗（failures.js）か説明文を指定
- `minigames` は順番に実行。点数（0〜1）が仕上がりに反映され、`failOn` 未満なら `failure` が起きる
- `when` で見積もり内容によって工程を切り替える（例：パッキン交換あり／なし）
- `retry: true` の失敗は、その工程をやり直しにする（ACリセット失敗、電池の逆向きなど）

## 評価
- 仕上がり点 = 100 − 失敗の減点 − 操作精度の減点 − 受付での不備の減点
- 星：90以上★5 / 75以上★4 / 60以上★3 / 40以上★2 / それ未満★1
- 報酬 = 見積もり × 星の割合（★5 100%, ★4 90%, ★3 75%, ★2 50%, ★1 25%）× 期限超過の減額 − 失敗による追加費用

## 測定値はシミュレーションから
時計ごとに内部状態（電池電圧など）を持たせ、測定器はそこから値を出す。
- 酸化銀電池：新品 約1.55V、1.50V 未満で交換。寿命末期は秒針が2秒運針（電池寿命予告）
- 新品電池でもまれに保管劣化（1.30〜1.44V）がある → 入れる前に測る意味がある
- 第2段階で、機械式の振り角・片振り・歩度を油の劣化やゼンマイの状態から計算する

## 段階ごとの計画
1. 工房を歩ける＋作業モード＋クォーツ電池交換（完了）
2. 機械式オーバーホール全工程（完了）＋見た目のリアル化＋タッチ操作（完了）
3. お金・ショップ・道具グレード・消耗品の購入（完了）
4. レベル・経験値・スキルツリー（精密作業／診断／仕上げ／経営・接客）
5. クリーニング、懐中時計、掛け時計・置き時計
6. 依頼のランダム生成、評判、セーブ/ロード、仕上げ

## 決めたこと（変更可）
- PCブラウザ前提（Pointer Lock）
- ゲーム内の時間は「日」単位。ショップ端末の「営業終了」で翌日へ（第3段階から）
- 音は第2段階以降で、ブラウザ内で合成して鳴らす（音声ファイルなし）
- ガイドは同じ作業を3回こなすまで自動表示。一時停止画面と G キーで切り替え可

## 第2段階で追加した仕組み
- 工程データの新項目：`optional` / `before`（やらなくても進めるが、飛ばすと `risks` で失敗が起きる）、`when.flag`（点検結果で工程が切り替わる）、`station`（洗浄機など作業台以外の工程）
- ミニゲーム：注油（油の種類＋量）、タイムグラファー調整（片振り・緩急）、最終測定、点検（ゼンマイのへたり判断）、防水テスト、洗浄機（槽の順番と時間）
- 機械式シミュレーション（src/sim/mechanicalSim.js）
  - 振り角 = 312 ×(0.55+0.45×ゼンマイ)×(1−0.32×汚れ)×(0.62+0.38×油) − ヒゲの変形
  - 歩度 = 緩急針の位置 + 0.22×(振り角−290)（振り角が低いと遅れる）
- 見た目：環境マップ（金属の映り込み）、影、ケースは断面の回転体、受けはコート・ド・ジュネーブ、地板はペルラージュ、青ネジ・ルビーの穴石、テンプとヒゲゼンマイが4Hzで振れる
- 入力：Pointer Events で統一。タッチ操作（仮想スティック・2回タップで使う・ピンチ）と、タッチパッド（ピンチ＝ctrl+ホイール）に対応
- 軽量化：ショーケースの時計は材質ごとにメッシュを結合、タブレットは描画解像度を1.5倍までに
- 道具はホットバー（1段10マス、1〜0キー）＋道具箱（Tab）。道具箱で選んだ道具は、いちばん長く使っていないマスと入れ替わり、並びはセーブされる
- 作業台のカメラは、手順パネル・ボタン・ホットバーを避けた「空いている部分」の中央に時計とトレイが来るよう、描く範囲と距離を画面の大きさに合わせて自動調整
- 仕上がり点の操作精度の減点は、工程の重み合計140（電池交換1回分）を基準に縮める（工程が多い作業で減点が積み上がりすぎないように）

## 第3段階で追加した仕組み
- お金の計算は `src/core/economy.js` にまとめ、画面（`src/ui/Shop.js`）と分けた。自動テスト `tests/economy.test.js`
- 帳簿 `state.ledger`：{ 日, 内容, 金額 }。修理代の入金・仕入れ・道具・家賃を記録し、1日の締めで集計
- 道具のグレード `state.toolGrades`：道具を種類ごとの「一式」でまとめて上げる（ドライバー4本を別々に買わせない）
  - 効果は `toolStats(state, toolId)` で取り出す：手ブレ倍率（力加減・角度・手ブレ・タイムグラファー調整のミニゲーム）、ルーペ倍率、オイラーの油の出る速さ
  - プロ用は評判が必要（評判は★3以上の返却で増える）
- 消耗品は注文するとすぐ届く（初心者向けの単純化）。見積もり画面で必要な部品の在庫と仕入れ値を見せ、利益の感覚をつかめるようにした
- 1日の締め：家賃・光熱費 1,000円/日。返却期限を過ぎると報酬が1日20%ずつ減る（最大50%）
- 工房の時計：文字盤を裏板から5mm浮かせてチラつき（同じ面の重なり）を解消。振り子時計はガラス扉の箱にして振り子が見えるように
- 道具はホットバーに SVG の絵（`src/ui/toolIcons.js`）。道具の名前は tools.js の name に1本化し、ヒントの「」内の道具名と一致するかをテストで確認
