# 設計メモ（時計修理工房）

## 目的
時計職人の実際の作業工程を、ブラウザの3Dゲームでリアルに体験できるようにする。
「正しい道具 → 正しい順番 → 力加減・角度・手ブレ・タイミングの操作」で工程が進み、
雑な作業は傷・紛失・破損として仕上がりと報酬に響く。

## 技術
- Three.js 0.170 + Vite 5（JavaScript）。3Dモデルはすべてコードのジオメトリで作る
- UI は HTML/CSS（日本語）、ミニゲームは Canvas 2D
- セーブは localStorage（キー `wr-games-save-v1`）
- テストは Vitest（ルールとデータの整合性）

## 3つの層
| 層 | 場所 | 役割 |
|---|---|---|
| データ | `src/data/` | 時計・部品・工程・道具・消耗品・お客さん・失敗。コードを書かずに増やせる |
| ルール | `src/procedure/`, `src/sim/` | 工程の進行判定、採点、時計の内部状態と測定値 |
| 表示 | `src/world/`, `src/bench/`, `src/watch/`, `src/ui/` | 3D と画面 |

## 工程データの考え方
- 工程は一本道ではなく **依存関係（needs）** で書く。`a|b` は「aかbのどちらか」
- `target`（クリックする部品）と `tool`（正しい道具）の組み合わせで工程が始まる
- `wrongTools` で、間違った道具を使ったときの失敗（failures.js）か説明文を指定
- `minigames` は順番に実行。点数（0〜1）が仕上がりに反映され、`failOn` 未満なら `failure` が起きる
- `when` で見積もり内容によって工程を切り替える（例：パッキン交換あり／なし）
- `retry: true` の失敗は、その工程をやり直しにする（ACリセット失敗、電池の逆向きなど）

## 評価
- 仕上がり点 = 100 − 失敗の減点 − 操作精度の減点 − 受付での不備の減点
- 星：90以上★5 / 75以上★4 / 60以上★3 / 40以上★2 / それ未満★1
- 報酬 = 見積もり × 星の割合（★5 100%, ★4 90%, ★3 75%, ★2 50%, ★1 25%）× 期限超過の減額 − 失敗による追加費用

## 測定値はシミュレーションから
時計ごとに内部状態（電池電圧など）を持たせ、測定器はそこから値を出す。
- 酸化銀電池：新品 約1.55V、1.50V 未満で交換。寿命末期は秒針が2秒運針（電池寿命予告）
- 新品電池でもまれに保管劣化（1.30〜1.44V）がある → 入れる前に測る意味がある
- 第2段階で、機械式の振り角・片振り・歩度を油の劣化やゼンマイの状態から計算する

## 段階ごとの計画
1. 工房を歩ける＋作業モード＋クォーツ電池交換（完了）
2. 機械式オーバーホール全工程（タイムグラファー、分解・洗浄・点検・注油・調整・防水検査）
3. お金・ショップ・道具グレード・消耗品の購入
4. レベル・経験値・スキルツリー（精密作業／診断／仕上げ／経営・接客）
5. クリーニング、懐中時計、掛け時計・置き時計
6. 依頼のランダム生成、評判、セーブ/ロード、仕上げ

## 決めたこと（変更可）
- PCブラウザ前提（Pointer Lock）
- ゲーム内の時間は「日」単位。第1段階では日付は進まない（閉店→翌日は第3段階以降）
- 音は第2段階以降で、ブラウザ内で合成して鳴らす（音声ファイルなし）
- ガイドは同じ作業を3回こなすまで自動表示。一時停止画面と G キーで切り替え可
